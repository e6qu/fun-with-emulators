# LTP system-call tests that fail on Linux too with this build and
# configuration (LTP_DEV_FS_TYPE=tmpfs, as tools/ltp/run.py runs them), and
# why.
# Every other test is to pass under fwe, but those for what is not planned
# for 1.0 (ROADMAP.md).
mq_open01 musl passes an empty queue name to the kernel, which gives ENOENT; the test expects glibc's EINVAL
sbrk01 musl's sbrk refuses any increment (ENOMEM) without asking the kernel
posix_fadvise02 Zig's libc posix_fadvise returns -1 and sets errno; the test expects the error returned
posix_fadvise03 Zig's libc posix_fadvise returns -1 and sets errno; the test expects the error returned
posix_fadvise04 Zig's libc posix_fadvise returns -1 and sets errno; the test expects the error returned
inotify03 it remounts its device and expects a file it wrote there; a new tmpfs (LTP_DEV_FS_TYPE) starts empty
mount02 a tmpfs (LTP_DEV_FS_TYPE) takes any source and stacks over itself, so its char-device, mounted-folder and invalid-device cases mount where a disk filesystem refuses
umount2_01 it remounts its device after MNT_DETACH and expects the file it wrote; a new tmpfs (LTP_DEV_FS_TYPE) starts empty
fmtmsg01 not built: musl has no addseverity
clone08 musl's clone() refuses CLONE_THREAD, CLONE_SETTLS and CLONE_CHILD_CLEARTID (EINVAL) without asking the kernel
clone10 musl's clone() refuses CLONE_THREAD, CLONE_SETTLS and CLONE_CHILD_CLEARTID (EINVAL) without asking the kernel
sigtimedwait01 musl's sigtimedwait retries a wait the kernel ends with EINTR, so the test's interrupted wait never returns
sigwaitinfo01 musl's sigwaitinfo retries a wait the kernel ends with EINTR, so the test's interrupted wait never returns
